# OPERATING CADENCE — Lanzalo

**Última actualización:** 2026-04-08
**Objetivo:** convertir la dirección de producto en una rutina operativa simple, repetible y medible.

## 1. Regla base

La cadencia existe para evitar dos fallos:

1. trabajar por impulso,
2. llenar el roadmap de tareas que no mueven activación.

Toda revisión, decisión o nueva tarea debe pasar por tres filtros.

| Filtro | Pregunta |
|---|---|
| Claridad | ¿Esto hace más entendible la promesa del producto? |
| Activación | ¿Esto mejora el flujo `idea -> viabilidad -> plan -> cofundador`? |
| Utilidad | ¿Esto aumenta la probabilidad de una primera acción útil? |

Si la respuesta es no a las tres, no entra.

## 2. Ritmo diario

### Daily de dirección

**Frecuencia:** una vez al día, máximo 20 minutos.

| Paso | Acción | Output obligatorio |
|---|---|---|
| 1 | Leer `docs/PROJECT-INVENTORY.md` | Confirmar que no se abrirá trabajo duplicado |
| 2 | Leer `docs/ACTIVATION_SCOREBOARD.md` | Ver el cuello de botella principal del funnel |
| 3 | Revisar `docs/EXECUTION_QUEUE.md` | Detectar tareas paradas, duplicadas o irrelevantes |
| 4 | Revisar errores críticos del flujo principal | Lista corta de incidencias reales |
| 5 | Elegir las 3 prioridades del día | Orden operativo del día |
| 6 | Asignar o reafirmar responsables | Propiedad clara |
| 7 | Bloquear trabajo lateral | Recorte explícito |

### Preguntas obligatorias del daily

| Pregunta | Qué busca |
|---|---|
| ¿Dónde se cae el usuario hoy? | Foco real |
| ¿Qué parte del flujo principal sigue rota o confusa? | Prioridad P0 |
| ¿Qué tarea abierta no mueve activación y debe congelarse? | Recorte |
| ¿Qué entregable se puede verificar hoy con evidencia? | Cierre basado en realidad |

## 3. Ritmo semanal

### Weekly review

**Frecuencia:** una vez por semana, 45 minutos.

| Bloque | Acción | Output |
|---|---|---|
| Funnel | Revisar conversiones E1 -> E8 | Diagnóstico semanal |
| Producto | Revisar fricciones del flujo principal | Lista de fricciones priorizadas |
| Operación | Revisar tareas cerradas vs impacto real | Limpieza de backlog |
| Mensaje | Revisar si la promesa pública coincide con el producto | Correcciones de copy o positioning |
| Decisión | Definir siguiente sprint o mantener el actual | Sprint activo actualizado |

### Regla de la weekly

No se aprueban nuevas líneas de producto en la weekly.

Sólo se puede decidir una de estas tres cosas:

| Tipo de decisión | Cuándo aplica |
|---|---|
| Reforzar | Una parte del funnel mejora y merece más inversión |
| Corregir | Un cuello de botella bloquea activación |
| Cortar | Una línea de trabajo no aporta señal real |

## 4. Ritmo de sprint

### Duración

Sprint corto de 7 días.

### Capacidad

Máximo 10 tareas activas con nombre y responsable.

### Regla de cierre

El sprint no se cierra porque “parezca bastante bien”.

Se cierra sólo si cumple:

| Criterio | Evidencia requerida |
|---|---|
| Promesa alineada | Landing y copy principal corregidos |
| Flujo principal estable | Recorrido sin bloqueos graves |
| Delegación visible | Estado y output trazables |
| Funnel medible | Eventos y tablero actualizados |

| Usuario / Board | Interviene sólo en decisiones de dirección, dinero o cambios de producción sensibles |

## 6. Protocolos de bloqueo

| Bloqueo | Acción correcta |
|---|---|
| Falta de acceso, credenciales o permisos | Escalar con detalle exacto del bloqueo |
| Una tarea lleva 3 intentos sin avance real | Parar, reescribir enfoque y reducir alcance |
| El equipo deriva a features laterales | Cancelar o posponer |
| Hay duda entre dos prioridades | Elegir la que mueva activación antes |

## 7. Reglas de calidad

Antes de marcar cualquier trabajo como hecho, comprobar estas cuatro cosas.

| Comprobación | Pregunta |
|---|---|
| Verificación real | ¿Se abrió la URL o artefacto final? |
| Integridad | ¿Hay rutas rotas, errores visibles o resultados incompletos? |
| Coherencia | ¿El cambio respeta la directiva de foco? |
| Impacto | ¿Mueve claridad, activación o utilidad? |

Si falla una, no se cierra.

## 8. Plantilla del daily operativo

Usar este formato.

| Campo | Contenido esperado |
|---|---|
| Fecha | YYYY-MM-DD |
| Cuello de botella principal | Una frase |
| 3 prioridades del día | Tres acciones concretas |
| Trabajo bloqueado | Sí / no + causa |
| Trabajo cancelado | Sí / no + motivo |
| Evidencia cerrada hoy | URLs, eventos o artefactos |

## 9. Plantilla de la weekly

Usar este formato.

| Campo | Contenido esperado |
|---|---|
| Semana | YYYY-WW |
| Conversión dominante | Qué tramo del funnel mejoró o empeoró |
| Fricción principal | Qué bloquea activación |
| 3 decisiones tomadas | Reforzar, corregir, cortar |
| Sprint siguiente | Mantener / cerrar / abrir nuevo |

## 10. Orden operativa final

La cadencia correcta no es:

- ideas nuevas,
- más módulos,
- luego medición.

La cadencia correcta es:

1. medir,
2. detectar cuello de botella,
3. corregir la fricción dominante,
4. verificar resultado,
5. repetir.

## 11. Criterio de autonomía

El sistema puede operar con autonomía táctica.

No puede cambiar sin validación del board estas cuatro cosas:

| Cambio sensible | Requiere validación |
|---|---|
| Cambios de monetización | Sí |
| Cambios de dominio o producción crítica | Sí |
| Gasto relevante en herramientas o tráfico | Sí |
| Cambio de foco de producto | Sí |

Todo lo demás puede ejecutarse si mejora el foco vigente.
